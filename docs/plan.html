Public intake, private backlog

Implement the authorized specification in dependency order. Task checklist.

Architecture

  1. Reuse the tested Apple reader and public-issue reconciler from Retain PR #3 in the new public repository.
  2. Add a conservative classifier and private-issue reconciler. Source markers and bot-owned sections make retries and edits safe.
  3. Run both stages daily in one public-repository workflow. Limit its own token to public repository contents/issues. Mint a separate short-lived GitHub App token for Retain Issues only.
  4. Write a status commit after each attempt, even on failure. Observe the next scheduled run because GitHub may delay or skip schedules.
  5. Supersede Retain PR #3. Retain gets backlog labels and issues, not a scheduled review workflow.

Order and checkpoints

  1. Create public repository and specify issue format, triage rules, secrets, failure behavior. Check: specification matches the user's requested topology.
  2. Port intake code and tests. Check: two-page fetch, no-op rerun, hostile public issue, edit, and partial failure fixtures pass.
  3. Add triage and private backlog reconciliation. Check: clear defect/request promoted, praise and vague text held, rerun no-op, edits preserve notes.
  4. Add public workflow and GitHub App permissions. Check: actionlint, no private runner, no untrusted PR event, scoped secrets and tokens.
  5. Configure live credentials, dispatch twice, inspect public and private results, then observe daily schedule. Apple API access remains an external prerequisite.

Risks and controls

  • Public issue marker spoofing: only trust bot-authored issues carrying the managed label; escape raw review text.
  • Cross-repository write access: GitHub App installed only on Retain with Issues read/write. Never place a personal broad GitHub token in public repo secrets.
  • False promotion: conservative deterministic rules; private issues say “needs triage,” not “confirmed bug.”
  • Quiet repository schedule shutoff: daily status commits provide meaningful activity; manual dispatch remains available. GitHub schedule delivery still needs monitoring.
  • Failure mid-run: scan all issue states on every run; fail visibly and recover without duplicate issues.
