Retain Feedback tasks

Each slice has a check. See specification and plan.

1. Public review intake

Depends on repository creation. Files: importer, tests. Medium.

  • Reuse scoped Apple token and validated pagination.
  • Create/update only trusted managed public issues; exclude user-created issues from reconciliation.
  • Verify first run, rerun, edit, bad data, spoofed marker, and partial failure with offline fixtures.

2. Private backlog triage

Depends on task 1. Files: triage module, tests. Medium.

  • Classify clear problems and requests conservatively; leave praise and ambiguous text public.
  • Create/update private Retain issues with stable Apple IDs, source links, and backlog labels.
  • Verify no duplicate, changed review, human-note preservation, and no automatic closure.

Checkpoint

  • Focused tests pass. No app UI opened. Test artifacts cleaned from the Mac.

3. Workflow and credentials

Depends on tasks 1–2. Files: public workflow, dependency pins. Medium.

  • Daily/manual standard public Ubuntu runner; safe permissions; serialized run; status commit.
  • GitHub App token limited to Retain Issues. Apple Customer Support key secret. No untrusted PR trigger.
  • Verify actionlint and complete diff; review secrets, review-text handling, schedule limits.

4. Activation

Depends on task 3 and Apple API approval. Small.

  • Install/configure GitHub App and Apple key; close superseded private PR.
  • Run workflow twice; verify public issue and private backlog behavior without duplicates.
  • Observe first scheduled run, or report its external blocker precisely.
